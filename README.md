# 图片表格转 Excel 助手 (img2excel-tool)

把**照片 / PDF 里的表格**识别出来，汇总整理成一个 Excel 文件。**完全离线运行**，不联网、不上传任何数据。

## 下载

到 [Releases](https://github.com/jianRY/img2excel-tool/releases) 下载，两个版本功能完全一样，按需选一个：

| 版本 | 适合谁 | 说明 |
|---|---|---|
| **单文件版** | 想拷到 U 盘/任意位置直接用 | 单个 exe，双击即用，**无需安装**。**支持程序内一键升级**；首次启动需解包约 120MB，慢几秒 |
| **安装版** | 长期在本机使用 | 装到 `C:\Program Files\Img2ExcelTool`，自动建开始菜单和桌面快捷方式，可卸载。**启动更快**；升级请重新下载安装包 |

> 安装版启动更快的原因：单文件版每次启动都要把内容解包到临时目录；安装版是解包好的目录结构，直接加载。

## 功能

- **格式支持**：JPG / JPEG / PNG / BMP / TIF / WEBP 图片，以及 PDF（自动逐页处理）
- **识别引擎内置**：RapidOCR 中文识别 + SLANet-Plus 表格结构还原，**不需要联网**
- **多文件汇总**：默认合并到同一张工作表，带「来源文件」「页码」两列；也可勾选**每个文件单独工作表**
- **金额自动修正**：对 OCR 的典型误判做保守修正，并在「列N原文」保留原始文本便于核对
- **数值格式**：纯数字自动转成数值格式（可求和、可排序），日期归一为 `YYYY/MM/DD`

### 自动修正规则

| 现象 | 原文 | 修正结果 |
|---|---|---|
| 千分位逗号被认成小数点 | `2.903.00` | `2903.00` |
| 千分位逗号残留 | `2,903.00` | `2903.00` |
| 小数点后误插空格 | `4. 69` | `4.69` |
| 数字间误插空格 | `2 903.00` | `2903.00` |

**模糊情形不猜测**：像 `12.345` 这种既可解释为十二点三四五、也可能是 `12345` 被误加小数点的，
程序**保持原样输出文本**，交由人工判断。只有在整数部分符合千分位分组规律时才改判。

## 使用

1. 点 **「选择文件」** 或 **「选择文件夹」**（自动扫描整个文件夹里的图片和 PDF）
2. 按需勾选：
   - **「输出『原文』列」**（默认开）：每个识别列右边跟一列原始 OCR 文本，便于核对自动修正。推荐保留
   - **「每个文件单独工作表」**（默认关）：多个文件版式差异大时打开，各表独立排版
3. 确认输出位置 → 点 **「开始转换」**
4. 点 **「打开输出」** 直接定位生成的 Excel

每张图 / 每个 PDF 页大约 1～5 秒（取决于照片大小和内容多少）。

## 自动更新

**单文件版启动时会自动检查新版本**，不用自己去下载页翻：

- 发现新版本 → 弹窗显示本次更新内容，三个选择：**立即更新 / 本次忽略 / 以后不再提醒**
- 下载过程显示进度与实时速度，**随时可取消**
- 下载完成后新版自动启动，旧版由新版清理掉
- 升级后文件名自动带上版本号（如 `图片表格转Excel助手_v1.2.2.exe`），一眼看出正在跑哪一版
- 也可以点程序**右上角「检查更新」**手动检查

> **安装版不参与自动更新**：程序装在 `C:\Program Files` 下，普通权限写不进去，就地替换会失败。
> 安装版升级请直接下载新的安装包覆盖安装。

## 注意事项

- **识别质量取决于原图**：拍照时尽量平整、光线均匀、正对拍摄。皱折、反光、印章遮挡会影响准确率
- **票据类图片属「无表格线」版式**：走「按行聚类 + 列位置对齐」的兜底算法，
  效果是「文字都识别到了、并按行列排开」，但**列的含义需要人工判断**
- **重要金额请人工复核**：用「列N原文」列对照，发现修正错误可立即定位

## 命令行

```bash
# 查看版本
图片表格转Excel助手.exe --version

# 无界面自检：会在输出文件旁生成 .selftest.log 日志
图片表格转Excel助手.exe --selftest <文件或文件夹> <输出.xlsx>

# 自检时不要「原文」列
图片表格转Excel助手.exe --selftest <输入> <输出.xlsx> --no-raw
```

### 开发机专属配置

发版/测试脚本需要知道几个**跟本机绑定**的位置（构建用的解释器、签名脚本、
Inno Setup、测试样本目录…）。这些**一律不写进仓库**，走 `devconfig` 的取值链：

```
环境变量  →  .pybuild_cache/local_config.json  →  通用默认值 / 相对路径
```

- 不配任何东西也能跑：解释器默认就用当前运行脚本的那个，交付目录默认取源码目录的兄弟目录
- 本机长期配置：把 `local_config.example.json` 复制成 `.pybuild_cache/local_config.json` 再按需填写（该路径已被 `.gitignore` 排除）
- 所有键都有对应的环境变量可临时覆盖，见 `local_config.example.json` 注释与 `devconfig.py`

### 入库前敏感信息扫描

本仓库是公开的，所以提交前会先扫一遍开发机信息与凭据：

```bash
python scan_sensitive.py              # 扫已入库文件
python scan_sensitive.py --staged     # 只扫暂存区
python scan_sensitive.py --history    # 扫全部 git 历史，找残留
```

扫描项：本机用户名/家目录/机器名、开发机工作区路径、用户目录路径、
盘符绝对路径（`Program Files` 等通用系统路径会放行）、GitHub 令牌、私钥内容、
硬编码口令、内联 URL 凭据、内部资料目录。

挂成提交钩子（每台机器一次）：

```bash
git config core.hooksPath .githooks
```

挂上之后每次 `git commit` 都会自动扫暂存区，命中即中止（确认为误报可用
`git commit --no-verify` 跳过）。

> 为什么卡在提交之前而不是事后清理：`git rm` 只从最新快照里删文件，**历史仍然
> 公开可查**。要真正清掉已推送的敏感数据，只能重写历史再强推，或者删库重建。

## 代码签名

所有发布的 exe 均使用 jianRY 自签名证书签名（SHA256 + RFC3161 时间戳）。

> 自签名证书只在本机（装过信任根）或拿到并安装 `.cer` 的机器上消除「未知发布者」提示。
> 公共分发场景下 SmartScreen 仍可能提示，这是自签名的固有限制。
